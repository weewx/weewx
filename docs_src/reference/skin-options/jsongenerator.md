# [JSONGenerator]

The section `[JSONGenerator]` specifies which files are to be generated by the
JSON generator `weewx.jsongenerator.JSONGenerator`. See [_The JSON
generator_](../../custom/json-generator.md) for how it works, and [_JSON data
files_](../json-files.md) for the format of the files that it writes.

The "look and feel" of how these data are presented is entirely up to the skin. 

## [[JSONFiles]]

The files to write. A subsection is a plot group, which is a family of files.
Its name begins the names of the files: for example, the plot group `tempdew`
writes `tempdew-2026-10-03.json` and so on. It is also the name that a skin
refers to, e.g., in the option `plot_groups` of *Horizon*.

Here is an example of two plot groups: `tempdew` and `rain`. Plot group
`tempdew` names two series as members: `outTemp` and `dewpoint`. Plot group
`rain` just one: `rain`.

``` ini
[JSONGenerator]
    [[JSONFiles]]
        [[[tempdew]]]
            [[[[outTemp]]]]
            [[[[dewpoint]]]]
        [[[rain]]]
            aggregate_type = sum
            aggregate_interval = 1h
            [[[[rain]]]]
```

Options set directly under `[[JSONFiles]]` apply to everything below it. An
option set lower down wins. By default, day files store the archive values
without further aggregation. Month and year files average these temperature
series at their configured resolutions. In this example, the `rain` group sums
over one hour, or over the file's resolution interval, whichever is longer.


## Plot group and series options

These options describe which numbers a JSON file holds. 

#### aggregate_interval

The time over which a series is aggregated, in seconds. Alternatively, a
[duration notation](../durations.md) can be used.  This option takes effect only
when it is longer than the resolution interval of the file (see section
[`[[Archive]]`](#archive)). For example, the resolution interval of Day files is
the native archive interval (typically 5 minutes), so `aggregate_interval`
has an effect only when it is longer than that. The same rule applies for
courser files. For example, the nominal resolution for Month files is 15
minutes, so `aggregate_interval` must be longer than 15 minutes to have an
effect.

#### aggregate_type

How the readings of an aggregation interval are combined. Choices include `avg`,
`max`, `min`, `sum` and `last`. Optional. Default is `avg`. Types that are
totals, such as `rain` and `ET`, are always summed, and `windDir` and
`windGustDir` always take the direction of the average wind vector, whatever this
option says.

#### data_binding

The database the series reads from, by the name of its binding. Optional. Default
is `wx_binding`.

#### data_type

The observation type used for the series. This allows a type to appear in a plot
group more than once, e.g., with different aggregate types. Optional. Default is
the name of the section.

The types `windvec` and `windgustvec` are wind vectors. A file holds their
components as well as their speed. See [_JSON data files_](../json-files.md).

#### unit

Normally, the unit used in a file is set by whatever [unit group the types are
in](../../custom/custom-reports.md#mixed-units). This option overrides the
unit of a plot group, e.g., `degree_C`. Optional.

## General options

#### json_dest_dir

Where the files go, relative to `HTML_ROOT`. Default is `data`.

#### round

How many decimal places to use when writing a value. Default is `2`.

#### include_daynight

Whether to write the times of sunrise and sunset, so a chart can shade the
night. Requires `pyephem`. Default is `True`.

## [[Archive]]

The archive is the whole database, cut into files the browser can fetch one at a
time. There are three tiers: one file per day for the last few days, all at the
archive interval; one file per month, at a shorter aggregation interval than the
years; and one file per calendar year, at an aggregation interval that grows
with age. The browser should pick the tier with the shortest aggregation
interval that covers the time it is showing.

The archive holds the plot groups of [`[[JSONFiles]]`](#jsonfiles). The files go
into subdirectory `archive`, located below [`json_dest_dir`](#json_dest_dir).

#### years

How many calendar years, counting back from this one, are written at
[`year_resolution`](#year_resolution). Older years use
[`old_year_resolution`](#old_year_resolution). Default is `2`.

#### year_resolution

The aggregation interval of the year files, for the years named by
[`years`](#years). May be a number of seconds or a duration such as `1h`.
Default is `1h`.

#### old_year_resolution

The aggregation interval of the older year files. A year at four hours holds
about 2,200 values per series. Default is `4h`.

#### months

How many calendar months, counting back from this one, are written at a shorter
aggregation interval than the year files, one file per month. Default is `2`.

#### month_resolution

The aggregation interval of the month files. Default is `900`, that is, fifteen
minutes.

#### days

How many days are written at the station's own archive interval, one file per
day. This is what the day view is drawn from. Default is `30`.

Files older than this are removed on the next run, so the storage cost of this
tier does not grow.

#### day_resolution

The aggregation interval of the day files. The default `0` uses the archive
interval.

#### budget

How many seconds a report may spend building the archive, as a number or a
duration. Default is `30`. A value of `0` removes the limit.

A report that runs out of budget starts no further file, and the next report
carries on from where it stopped. The newest files come first, so the older
years fill in over the next reports.

The day tier is never deferred. It is what the day view is drawn from, and a
page without today is of little use.

#### extremes

Comma separated list of observation types that also carry their lowest and
highest value in each aggregation interval, not only the aggregate. An average
is the wrong thing to remember for a gust: averaged over four hours, a storm
turns into a breeze. Each name costs two more queries per aggregation interval.
Default is `windGust, windSpeed, rainRate, UV`.

#### rebuild

How often every file is built from the whole database again, rather than
carried forward from the one already on disk. Default is `0`, which never does.

A file that has been written is correct for the time it covers, and the archive
index is checked against the directory on every run. Set it to a number of hours
to have the files rewritten anyway, for a station whose history has been edited.
